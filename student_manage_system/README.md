# 学生管理系统设计

## 项目简介

本项目计划实现一个基于 C++ 的学生管理系统，采用面向对象设计和文本文件持久化数据。系统以学生信息和成绩管理为核心，支持管理员与学生两类用户；
当前仓库处于基础骨架阶段，本文档描述目标设计，不代表其中所有功能均已实现。

## 设计目标

- 使用类与对象组织用户、学生和成绩数据。
- 按职责拆分认证、学生管理、成绩管理和文件读写逻辑。
- 根据用户角色提供不同菜单和权限。
- 通过文本文件保存数据，程序重新启动后能够继续使用。
- 对重复学号、无效成绩、文件读写失败等情况提供明确提示。

## 功能范围

### 第一阶段：核心功能

| 模块 | 功能 |
|---|---|
| 账号与权限 | 用户登录、学生注册、修改密码、区分管理员和学生角色 |
| 学生信息 | 新增、查询、修改、注销学生信息 |
| 成绩管理 | 录入、查询学生成绩，按学生或课程统计成绩 |
| 数据持久化 | 从文件加载数据，新增或修改后保存数据 |



扩展模块应在核心功能稳定后再接入，并复用统一的用户身份、文件读写和菜单调度机制。

## 用户角色与菜单

### 未登录

1. 登录
2. 学生注册
3. 退出

### 管理员

1. 学生信息管理
2. 成绩管理
3. 修改密码
4. 保存并退出

### 学生

1. 查看个人信息
2. 查询个人成绩
3. 修改密码
4. 退出

管理员菜单提供完整的数据维护权限；学生只能查看自己的信息和成绩，不能修改成绩或查看其他学生的个人数据。

## 类与职责

| 类 | 职责 |
|---|---|
| `User` | 保存用户身份和登录相关信息；提供必要的访问和修改接口 |
| `Student` | 保存学号、姓名、性别、专业、班级、入学年份和联系方式 |
| `Score` | 表示一条成绩记录，包含学号、课程、学分、成绩和学期 |
| `AuthManager` | 处理登录、注册、密码修改和角色校验 |
| `StudentManager` | 处理学生信息的新增、查询、修改和注销 |
| `ScoreManager` | 处理成绩录入、查询、平均分和统计 |
| `FileManager` | 统一负责数据文件的加载、解析、保存和错误报告 |
| `CampusSystem` | 启动系统、控制登录状态并调度相应菜单和管理模块 |

核心关系：

```text
User 1 ── 0..1 Student
Student 1 ── * Score
```

用户账号通过用户编号或学号与学生资料关联；成绩记录通过学号关联学生。

## 数据文件设计

第一阶段使用文本文件存储，每行一条记录，字段之间使用 `|` 分隔。读取数据时应检查字段数量和格式；字段内容不得直接包含分隔符，或需在读写时提供转义处理。

| 文件 | 字段格式 | 用途 |
|---|---|---|
| `users.txt` | `userId|username|passwordHash|role|status` | 登录账号、密码摘要、角色和账号状态 |
| `students.txt` | `studentNo|name|gender|major|className|enrollYear|phone|status` | 学生基本信息 |
| `scores.txt` | `studentNo|courseId|courseName|credit|score|semester` | 学生成绩记录 |

密码不得以明文形式保存。用户注册时应检查用户名和学号是否重复；学生注销时优先将账号或学生状态标记为停用，避免直接删除后造成成绩记录失去关联。

## 关键业务流程

### 登录

1. 输入用户名和密码。
2. 查找账号并校验密码摘要及账号状态。
3. 根据用户角色显示管理员或学生菜单。
4. 学生访问成绩时，仅查询与当前账号关联的学号。

### 学生注册

1. 输入用户名、密码和学生基本资料。
2. 检查用户名和学号是否已存在，并验证必填字段。
3. 创建用户账号和学生记录。
4. 保存到 `users.txt` 和 `students.txt`；如保存失败，向用户明确报告错误。

### 成绩录入

1. 确认目标学生存在且未注销。
2. 校验课程信息、学分和成绩范围。
3. 新增或按系统规则更新成绩记录。
4. 保存至 `scores.txt`，并提示操作结果。

### 学生注销

1. 确认目标学生存在。
2. 将学生和账号状态设为停用，而不是直接删除关联数据。
3. 保存变更，并保留历史成绩供查询或统计。

## 工程结构

```text
student_manage_system/
├── include/
│   ├── user.h
│   ├── student.h
│   ├── score.h
│   ├── auth_manager.h
│   ├── student_manager.h
│   ├── score_manager.h
│   └── file_manager.h
├── src/
│   ├── main.cpp
│   ├── auth_manager.cpp
│   ├── student_manager.cpp
│   ├── score_manager.cpp
│   └── file_manager.cpp
└── data/
    ├── users.txt
    ├── students.txt
    └── scores.txt
```

头文件放在 `include/`，实现文件放在 `src/`，运行时数据放在 `data/`。构建配置可根据项目需要使用 Makefile 或 CMake。

## 实现建议

1. 先定义 `User`、`Student` 和 `Score` 的数据结构及接口。
2. 实现文件加载、保存和输入校验。
3. 完成登录、角色菜单和学生信息管理。
4. 完成成绩录入、查询和统计。
5. 验证数据文件缺失、格式错误、重复记录和无效输入等情况。
6. 核心流程稳定后，再考虑图书管理和账户管理扩展。
